# 見て判断し、その場で返せる資料への刷新 設計 spec（visual-explain）

## Overview

visual-explain の生成資料を、「読ませる資料」から「見て判断に到達し、その場で回答・指摘を agent へ返せる資料」へ刷新する。4 Phase に分け、各 Phase は単独で出荷できる。実装計画は Phase ごとに別に書く。

### 背景（2026-10-07 の問題分析の要約）

同梱見本 `skills/visual-explain/examples/example-proposal.html` の実測と UI 評価で、次を確認した。

| 不満 | 実測 |
|---|---|
| 文字量が多い | 本文 2,000 字。最初の図まで 612 字（約 2 画面下）。同一主張を h1・副題・目次・h2・claim・図キャプション・ask・回収パネルで 3〜5 回反復。図は縦の 32% |
| 図が 12 形式に固定 | 正規見本でも canonical 図は matrix 1 点のみ、主図は compatibility。`SKILL.md` は自由 SVG を許すが、checker の SVG 許可タグは 8 種（`path` なし）で、allowlist は slope のみ |
| 本文を指して返せない | 判断の回収パネルとコピーは既存。段落・文字列を指して種類付きで指摘する層がない |
| UI に高揚感がない | テーマ切替は 20 字の文字ボタンで h1 より目立つ。アイコン 0。コピーボタンが背景と同色。スマホ余白 8px。UI 評価 19/36 |

根本原因は「LLM=what / build=how」「skeleton 1 バイト不変」「見た目刷新は non-goal」（`2026-08-13-visual-stage-deck-design.md`）が、検査通過性を読者体験より優先させてきたことにある。本 spec は決定論と検証四層を保ったまま、読者体験側を引き上げる。

### 北極星

- 第一画面で「結論」と「全体図」が見え、図の番号 ①②③ から判断の場所へ飛べる。
- 読者は問いカードで選び、段落を指して指摘し、コピー 1 回で agent へ返す。
- agent は返ってきた固定形のテキストだけを読んで反映し、必要なら `-02` 版で再往復する。

### 確定した設計判断（ブレインストーミングでの決定）

| 論点 | 決定 |
|---|---|
| 回答・指摘の仕組みの置き場所 | 資料型は増やさず、既存 3 型（proposal / system / research）すべてに問いカード・指摘層・回収パネルを重ねる |
| 第一画面 | 題名 → 結論（3 文以内）→ 全体図 1 枚。副題と目次は廃止し、①②③ が目次を兼ねる |
| 番号の色 | 既存の青系（`--accent`） |
| 回答の場所 | 問いカードの中で選ぶ。末尾の回収パネルは集計とコピーのみ |
| 指摘の操作 | 指した段落の真下に入力を開く。段落ホバー（スマホはタップ）の ＋ と、文字なぞりの小ボタン |
| 指摘の種類（チップ） | 8 種: わからない / 図にしてほしい / もっと詳しく / 短くする / 削る / 言い換える / 事実を確認 / ここは良い |
| 見た目の方向 | 静かな精密（現行の延長を磨く）。装飾は足さず「どこを見るか」を強くする |
| テーマ切替 | アイコンのみ（ライト / ダーク）。「自動」の選択肢は置かない |
| 個別図 | 格子上の配置まで agent が宣言し、座標・線・色はビルドが決める |

### Hard constraints（全 Phase 共通）

- **既存配色のみ**: skeleton の既存トークンと、それを `color-mix` で薄めた色だけを使う。新しい色相を持ち込まない。
- **外部依存ゼロ**: build / check は Python 標準ライブラリのみ。JS テストは node 標準のみ。フォントはシステムフォント。
- **決定論フロア**: agent は what（構造・配置・文言）を書き、how（座標・線・色・DOM）はビルドが決める。
- **検証四層**: `check.sh` が全 Phase で通る。生成 HTML の手編集は禁止で、修正は IR → 再ビルド。
- **skeleton は版ごとに不変**: 「1 バイト不変」を「版ごとに 1 バイト不変」に改める。checker は文書が宣言する版の skeleton と照合する。既存の v1 生成物は引き続き検査に通る。
- **外部の固有名を持ち込まない**: 参考にした他者のスキルの名称を、コード・コメント・コミット・リポジトリ文書に書かない。仕組みは一般語（問いカード、指摘層、回収パネル、試問）で表す。

## Phase 1 — 読み順と反復の削減

### first-screen IR

- 追加: `conclusion`（必須。1〜3 文、1 文 80 字以内）、`overview`（全体図の指定と ①②③ の行き先）。
- 廃止: `decision`（Phase 2 の問いカードへ移る）、`conditions`（結論に含める）、`document.summary` の副題表示（summary はメタ情報として残すが描画しない）。
- `overview` の形:

```json
"overview": {
  "section": "sec-approval-map",
  "markers": [
    { "n": 1, "label": "限定対象で開始するか", "target": "sec-ask-decision" },
    { "n": 2, "label": "撤回条件の承認者", "target": "sec-ask-owner" }
  ]
}
```

- `section` は canonical セクションの id。そのセクションを第一画面内に移して描画する。
- `markers` は 1〜5 件。`n` は 1 からの連番、`target` は文書内のセクション id。
- 全体図は「h2 を持つ節が 3 つ以上、または ask が 3 つ以上」の資料で必須。それ未満では省略できる。
- Phase 1 では ①②③ は図の直下に番号付きリンク一覧として描く（図要素への重ね描きは Phase 4）。

### 描画

- 第一画面: `h1`（`document.title`）→ 結論ボックス（左に `--accent` の縦線）→ 全体図 → 番号一覧。
- 目次（現行は見出し 5 つ以上で自動生成）は廃止する。`data-ve-section-kind="toc"` を新規生成しない。

### 反復の検査（validation、fail-closed）

| 検査 | 不合格条件 |
|---|---|
| h2 と claim | h2 と直後の `.claim` の文字 bigram Jaccard 係数が 0.6 以上 |
| 図キャプションと h2 | キャプションと図の直前の h2 の Jaccard 係数が 0.6 以上 |
| 同一文の重複 | 句読点・空白を正規化した同一文が文書内に 2 回以上（ビルド自動生成の回収パネルは除外） |
| 図までの距離 | 全体図を持たない文書で、最初の図より前の本文（h1 と結論を除く）が 200 字を超える。全体図を持つ文書は第一画面の構造（h1 → 結論 → 全体図）で保証されるため対象外 |
| 結論 | 4 文以上、または 1 文が 80 字超 |

文の区切りは「。」「？」「！」とする。診断文言は日本語で、完全一致テストの対象にする。

### 文字量の報告

ビルド成功時に標準出力へ「本文 N 字 / 図より前 M 字 / 図 K 点」を出す。不合格にはしない。

### 移行

- assembly schema の版を上げる。新しい版で廃止項目（`decision` / `conditions`）を書くとエラーにする。旧版 IR の読込・自動移行は提供しない（IR は資料ごとに agent が書き直す前提）。
- 同梱見本と fixture を新しい版へ書き直す。見本内の「見本のための想定です」注記は closing の 1 か所に集約する。
- `SKILL.md` と `references/patterns.md`、`references/assembly.schema.json` を更新する。
- 既存の生成済み HTML は `check.sh` で引き続き合格する。

### テスト

- 反復検査 5 種それぞれの合格 / 不合格 fixture。
- 見本の再ビルドで、本文 1,400 字以下、かつ全体図より前が h1 と結論だけであることを確認する。
- `check.sh --selftest` と全テストの通過。

## Phase 2 — 問いカード・指摘層・回収パネル（skeleton v2）

判断エンジンとコピー処理は skeleton の固定領域（`assets/skeleton.html` の `FIXED DECISION ENGINE CORE` 〜 `FIXED DECISION COLLECTION JS`）にあるため、Phase 2 で skeleton の版管理を導入し、動作を変えた **skeleton v2** を出す。

### skeleton の版管理

- skeleton を `assets/skeleton-v1.html`（現行のバイト列そのもの）と `assets/skeleton-v2.html` に分ける。ビルドは常に最新版を使う。
- 生成文書は使用した skeleton 版を自己表明する属性を持つ（v1 文書は属性なしを v1 とみなす）。checker は宣言版の skeleton と固定領域を照合する。
- 既存の v1 生成物と v1 fixture は変更なしで合格する。

### 問いカード（`askType: "decision"`）

- 選択肢は `benefit`（利点）と `tradeoff`（代償）を必須とする。推奨でない選択肢に `benefit` が無ければエラー。
- 推奨は既存の `defaultId` で示し、「推奨」バッジを付ける。未選択は「お任せ＝推奨」として扱う。
- `evidence`（`file:line` または実行結果の引用）を必須とする。事実を人に聞かないため。
- decision ask は 1 資料 4 問まで。5 問以上はエラー。
- カード内で選択（ラジオ風）と補足の記入ができる。
- 再往復用に選択肢の `withdrawn: true` を受け付け、取り消し線付きで残す（選択不可、回答に含めない）。
- `hypothesis` / `request` 等の他の ask は内容を変えず、カードの見た目だけ揃える。

### 指摘層

- 対象ブロック: content 区間内の `p, h2, h3, li, figure, blockquote, pre, table`（回収パネルと問いカードの UI 部品は除く）。
- ビルドが DOM 順に `data-ve-blk="N"`（1 からの連番）を付与する。予約属性とし、checker が連番の欠落・重複・対象外タグへの付与を検査する。
- 操作: 段落ホバー（タップ）で ＋、文字なぞりで「指摘」小ボタン。指したブロックの直下に、8 チップ＋ひとこと欄を開く。
- 指摘済みブロックは左に `--accent` の縦線と `#N` 札を表示する。
- 1 ブロックに複数の指摘を付けられる。なぞった場合は引用（先頭 40 字）を記録する。
- キーボード操作: ブロックにフォーカスして Enter で開く。チップは `role="radio"` 相当の単一選択。

### 回収パネル

- decision ask の有無に関わらず、全資料の closing の後に 1 つだけ生成する（現行の「decision ask があるときだけ」を改める）。checker の不変条件も「ちょうど 1 つ」に変更する。decision ask の digest 照合は維持する。
- 下書き（選択・補足・指摘・全体メモ）を localStorage に自動保存する。キーは文書 id と schema 版から作る。保存に失敗しても画面は動く。
- コピーの固定形:

```
[visual-explain 回答]
資料: <title>
(<path> / id: <id> / schema: <ver> / asks: <digest>)
Q1. <問い>: <選択> / 補足: <自由記述>
Q2. <問い>: (未選択 = お任せ)
全体メモ: <自由記述>
## 指摘
#12 [図にしてほしい] 「<なぞった文字列（先頭 40 字）>」 <ひとこと>
#15 [ここは良い]
---
上の回答を反映して作業を続けてください。お任せの項目は推奨案で確定してください。
```

- 空の節（指摘 0 件など）は出さない。補足が空なら ` / 補足:` を省く。
- クリップボードが使えない環境では、現行どおり手動コピー用の表示に切り替える。

### SKILL.md のワークフロー追加

1. **試問**: 資料を開く前に、文脈を持たない general-purpose subagent に資料の絶対パスと読者宣言 1 行だけを渡し、5 問で検査する。同期で結果を待つ。
   1. 選択肢の弁別（各選択肢を選んだときの違いを資料だけから説明できるか）
   2. 根拠の引用の有無
   3. 実質 1 択の検出（推奨でない選択肢を選ぶ理由が読めるか）
   4. 音読と 30 秒 3 文要約
   5. 説明なしの内輪語の列挙
   - decision ask の無い解説資料では 1〜3 を省く。
   - 落ちた問いは「絵を足す / 問いを落とす / 言い換える」で直し、同じ subagent に差分だけを送って再判定する。計 2 巡で打ち切る。
2. **待つ**: 資料をブラウザで開いたら、回答の貼り戻しが届くまで実装を始めない。
3. **反映**: 固定形を読み、お任せの問いは推奨案で確定する。設計が変わる指摘なら `<topic>-02` で作り直し、捨てた案は `withdrawn` で残す。生成した資料は証跡として消さない。

### テスト

- 問いカード: benefit 欠落・evidence 欠落・5 問・withdrawn の合格 / 不合格 fixture。
- `data-ve-blk` の連番・対象タグ検査。
- コピー固定形: node 標準の JS テスト（既存の decision engine テストを拡張）。指摘あり / なし、お任せ、補足空、withdrawn を網羅。
- 回収パネルの常設（decision ask なし文書でも 1 つ）。
- v1 生成物の後方互換。

## Phase 3 — 見た目の刷新（skeleton v3）

### 書体と余白

- 書体サイズを 1.25 倍刻みに整理: 本文 1rem / 補助 .8rem / h3 1.25rem / h2 1.563rem / h1 1.953rem。
- first-screen の `min-height: 60vh` を廃止。`section` の `margin-block` を 5.5rem から 3rem に詰める。
- 背景面（`--surface`）は全体図にだけ敷く。

### 操作部品

- 主ボタン（コピー、①から答える）は `--accent` 塗り＋白文字。副ボタンは枠線のみ。
- 問いカードの選択肢: 1px 枠、ラジオ風の丸印、ホバー表示。選択中は `--accent` 枠と `--accent` を薄めた背景。
- 「JavaScript が有効なときに使えます」の注記は JS 初期化後に非表示にする。

### テーマ切替

- 32px の円形ボタンに、インライン SVG の太陽 / 月アイコンのみを置く（`currentColor`）。
- `aria-label` と `title` に「テーマ: ライト（ダークに切替）」の形の文言、`aria-pressed` を持つ。
- 「自動」の選択肢は置かない。初回のみ OS の `prefers-color-scheme` を初期値にし、押した後の選択は localStorage に保存する。

### モバイル

- 左右余白を 16px にする。
- 42rem 以下では matrix を案ごとのカード（縦積み）に切り替える（matrix の component CSS を更新し、registry の digest を更新）。

### 動き

- ホバーと選択の状態変化にのみ 150ms の遷移を付ける。`prefers-reduced-motion` では付けない。無限アニメーションは引き続き禁止。

### 検証

- UI 評価（critique）を再実施し、19/36 から 28/36 以上を目標にする。
- v3 skeleton の固定領域照合、v1 / v2 生成物の後方互換、fixture と selftest 期待値の更新。

## Phase 4 — 個別図（13 番目の canonical 形式 `grid-diagram`）

### IR

```json
{
  "relationship": { "kind": "spatial-layout", "capabilities": ["spatial-placement"] },
  "selection": { "component": "grid-diagram", "version": 1, "matchedCapabilities": ["spatial-placement"] },
  "claim": "根拠と顧客影響は共同承認で合流し、撤回条件が公開を見張る",
  "grid": { "cols": 4, "rows": 3 },
  "nodes": [
    { "id": "exception", "label": "契約例外", "cell": [1, 1], "tone": "base" },
    { "id": "approval", "label": "共同承認", "cell": [3, 2], "tone": "primary" },
    { "id": "rollback", "label": "撤回条件", "cell": [4, 3], "tone": "warning" }
  ],
  "regions": [ { "id": "legal", "label": "法務", "from": [1, 1], "to": [2, 1] } ],
  "edges": [ { "from": "exception", "to": "approval", "label": "照合" } ],
  "markers": [ { "n": 2, "target": "approval", "ask": "sec-ask-owner" } ],
  "caption": "図 2 — 何を見るか: 二つの根拠が共同承認で合流する位置"
}
```

- `grid` は列・行とも 1〜6。`cell` は 1 始まりの [列, 行]。`span`（[幅, 高さ]）は任意。
- `nodes.label` は 14 字以内、`edges.label` は 10 字以内。
- `tone` は `base`（`--dg-primary-light`）/ `primary`（`--dg-primary`）/ `warning`（`--dg-negative` の枠）。
- `markers` は 1〜5 件。`target` はノード id、`ask` は任意で問いカードのセクション id。

### レンダラ

- 1 マスの寸法を固定し、整数座標で配置する。viewBox は列・行数から決まる値とし、checker も同じ式で期待値を計算する。
- 線は直交 1 回折れ（水平 → 垂直、または垂直 → 水平）で、`line` 要素の組で描く。矢じりも短い `line` 2 本で描く。SVG の許可タグ集合は増やさない。
- 番号マーカーは対象ノードの右上に `circle` ＋ `text`（`--accent`）で描く。
- 読み上げ用に、ノードと関係の一覧（「契約例外 → 共同承認（照合）」）を図の直後に自動生成する。

### fail-closed の検査

| 検査 | 不合格条件 |
|---|---|
| 重なり | 2 つのノードが同じマスを占める |
| 囲み | ノードが囲みの境界をまたぐ |
| 線の横切り | 線分が端点以外のノードの矩形を通る |
| 文字数 | ラベルが上限を超える |
| 参照 | `edges` / `markers` / `regions` の参照先が存在しない、格子の外を指す |

不合格時は自動で配置を直さず、診断を返して agent に再配置させる。

### 他の Phase との接続

- first-screen の `overview.section` が `grid-diagram` の場合、①②③ をノード上に描く（番号一覧も併記する）。
- 問いカードの選択肢に `figure`（3×3 以下の `grid-diagram`）を付けられる。見た目が違う選択肢は両方に図を付ける。

### SKILL.md

- 「配置そのものが意味を持つとき（近さ＝関係、上下＝優先、囲み＝責任範囲）だけ `grid-diagram` を使う。12 形式で表せるならそちらを使う」を追記する。
- 自由 SVG を許す記述（現行 `SKILL.md` の「ライブラリで表せない場合だけ自由なインライン SVG」）は、`grid-diagram` を使う指示に置き換える。

### テスト

- レンダラ単体（座標・viewBox・線の折れ・マーカー位置）。
- SVG 二重ゲート（許可要素・属性・整数座標・viewBox 期待値）。
- 検査 5 種の合格 / 不合格 fixture。
- 選択肢の小図と first-screen のマーカー重ね描き。

## Non-goals

- 読者が本文を直接書き換えて完成形を返す編集機能。
- 新しい資料型の追加、外部フォント、外部 JS、サーバ。
- 自動レイアウト（ノード位置の自動決定）。
- 旧版 IR の自動移行。

## 用語

- **問いカード**: 判断を求める ask を、選択肢ごとの利点・代償・推奨・お任せ・補足でカード内に完結させた部品。
- **指摘層**: 本文ブロックを指して、種類（チップ）とひとことを付ける層。
- **回収パネル**: 回答と指摘を集計し、固定形のテキストとしてコピーする末尾の部品。
- **試問**: 資料を人に見せる前に、文脈を持たない subagent に読ませて伝わるかを検査する手順。
